# 项目设计原则

### IM 斜杠命令扁平化

内容：IM 里的斜杠命令不用"命令 + 子命令"的层级结构（如 `/schedule run`）。命令就是命令，需要复合语义时用横杠连接成一个词（如 `/schedule-run`、`/schedule-bind`），解析简单、意图明确。

适用场景：所有 IM 侧（飞书/企微/微信）斜杠命令的设计。

### 用超时兜底替代并发状态机

内容：对"任务/作业"类功能，不为并发冲突引入配置项（如 overlap: skip/queue/restart）。改为每个任务声明最大执行超时，生命周期只有两个终态：完成或超时。每次触发都是全新的独立执行，靠隔离性而非互斥策略保证正确性。

适用场景：定时任务、后台作业等"触发-执行-结束"型功能。前提是每次执行完全独立、无共享状态。

### 任务会话隔离，只借用投递能力

内容：由 bridge 主动发起的工作（如定时任务）必须运行在独立的临时会话中，绝不触碰用户聊天的会话绑定；只在最后把结果通过 Client Adapter 的正常投递管线发到指定聊天。

适用场景：任何 bridge 侧主动触发、需要把结果推送到 IM 会话的功能。
